# Revisions: from feedback to a new version

## Turn each note into a change

| Owner says | Concrete change |
|---|---|
| "Make it shorter" | Propose what to drop to reach the target, with the new sum; ask if the target is not given |
| "Move the CTA earlier" | Move the CTA segment; recompute every position after it |
| "Take out the part about X" | Remove the segments containing X; check the remaining lines still make sense |
| "The start is boring" | Offer 2–3 alternative hooks from lines that were actually said |
| "Captions bigger / different colour" | Change the style; record it in the profile |
| "Add music" | Mood and licensed source; see `polish.md` |
| "Say that we offer a free consultation" (not said in the video) | Cannot be added to captions or as a spoken line. Offer: a text card **if the owner confirms it is true and approves the wording**, or record a new line |

## Every revision

1. New version folder or label (`v2`). Never overwrite `v1`.
2. Apply only the requested changes; do not "improve" other parts silently.
3. Recompute: segment table, **sum = new length**, caption times, cue times.
4. Changelog, one line per change: `v2: removed 00:24.1–00:31.0 (dental floss tip); CTA moved to
   00:38.2; length 52.6 → 45.7 s`.
5. Ask for approval of `v2`.

## Learn

If a note is a lasting preference ("I never want music under the hook", "always keep my laugh"),
record it in the profile and say you did. If a note is about this video only, record it in the
project memory.

## When notes conflict

Two notes that cannot both be true ("keep everything" and "under 30 seconds"): show the trade-off with
numbers and ask which wins. A note that breaks a rule (invent a claim, use a commercial song, publish
without approval): explain in one sentence and offer the closest safe option.
